# Per-message transcript translation

The open Transcript tab translates visible, nonempty `THEY` entries into the configured translation language. It requests the newest visible entries first and keeps at most three requests active in this view. `ME` entries stay in their original form. **Show originals** pauses new requests and cancels outstanding ones; switching back reuses completed translations. Failed entries show their original text and an explicit Retry action.

The renderer caches results by session, entry ID, language and source content for the current view. This cache is temporary and does not modify or export transcript entries. A changed entry invalidates its cached result; a removed session or cancelled request cannot return a usable translation. The main process rechecks the source after generation and uses the independently configured translation provider/model, or the selected analysis route when no separate translation route is configured. Local routes use the owned model lease and normal context preflight. The existing Translation tab still generates and saves one whole-transcript translation.

Verification: `test/entry-translation.test.cjs` checks eligibility, preflight, cancellation, changed source and non-persistence. The full backend suite passed 134/134 outside the restricted shell environment, where loopback listeners are permitted. UI tests passed 29/29; the TypeScript/Vite build and JavaScript syntax check passed. The local browser mock confirmed translated and original presentation at desktop and phone widths. Its provider returned controlled local fixture text. Real model quality and long-session behavior remain unmeasured. A visual comparison was reviewed on a local board.
